指针与数组

一。C++
数组与指针
刚开始的时候感觉这个挺莫名其妙的，但其实这两个描述了数据怎样排列在内存里，程序怎样找到它，以及怎样减少不必要的数据搬运。
假设一个int占4个字节，那么一个数组中的相邻元素所占的地址就相差4，指针变量就保存着这个地址，同时它自己也有一个地址，*指针变量就是☞指针变量保存地址中的元素，修改 p，是在改变“去哪里找”；修改 *p，是在改变“那里存的内容”

a[i] == *(a + i)指针和数组是可以相互表示的

那为什么指针和数组能够相互表示，还要这两个概念干什么，为什么不合并成一个概念

其实这两个应该是配套使用的，数组将多个相同类型的对象组织为一个具有固定元素数量和连续存储布局的整体，指针的存在方便在不同的数组间活动，比方说我想实现

int a[3] = {1, 2, 3};int b[3] = {4, 5, 6};
int *p = a;
cout << p[0];  // 1
p = b;
cout << p[0];  // 4

这里 p可以随时改变指向的对象，但数组做不到

所以说如果要合并的话，就要定义一个量，使得其满足

1.创建并拥有一块连续数据；

2.在不复制数据的情况下引用另一块数据

一维数组很好理解，但到二维，三维数组时，其实会增加更多的细节和性质，这是为啥呢

二维数组可以理解为“元素是一维数组的数组”，可能我们的大脑理解多维数组时，需要同时处理几种不同的结构，而这些结构并不完全一致。它让原本重合的“元素、类型、位置、地址”四种概念开始分层。我们需要同时协调这些层次，认知负担才明显增加。

就像一个四维数组，int a[2][3][4][5]，可以这样理解

a是一个包含 2 个元素的数组，每个元素都是包含 3 个元素的数组，每个元素又是包含 4 个元素的数组，最内部每个数组包含 5 个整数。然后内存的储存方式就也是线性的

来看这样一个问题

比方说做一个简单的花销记录，输入你周一到周日每天的花费，计算一周总花费，平均每天花费，花费最多的是星期几；若并列，输出最早的一天。

#include <iostream>using namespace std;int main() {    double cost[7], sum=0;    int best=0;    for (int i=0; i<7; ++i)     {        cin>>cost[i];        sum+=cost[i];        if (cost[i]>cost[best]) best=i;    }    cout<<"总花费："<<sum<<'\n';    cout<<"日均花费："<<sum/7<<'\n';    cout<<"花费最多：星期"<<best+1<<'\n';}
